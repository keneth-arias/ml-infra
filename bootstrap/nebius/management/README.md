# Worker allocation and cleanup

## Check the allocation

Keep the reviewed source, backend key, provider lock and off-host ledger under operator control. Write the scope JSON in a private file. The guard expects these keys.

| Key | Input |
|---|---|
| `project_id`, `subnet_id`, `cluster_id`, `run_id` | Independently approved target and unique run |
| `start`, `cutoff` | UTC `Z` timestamps, up to eight hours apart |
| `accrued_gpu_hours`, `remaining_gpu_hours`, `accrued_gpu_usd`, `accrued_non_gpu_usd` | Cumulative ledger across all windows |
| `cpu_and_boot_disk_usd_per_hour` | Fresh quote for one regular CPU worker plus 128 GiB boot SSD |
| `other_remaining_usd`, `cleanup_reserve_usd` | Itemized non-GPU retention, transfer, management, tax and contingency. The guard adds CPU and boot SSD through cutoff plus one hour separately. |

Check an exact saved plan from the Terraform root using `./with-credentials ./check-cpu-plan "$plan" "$scope"`. The guard is read-only. It checks the embedded Terraform source, expected provider defaults, topology, run ownership, plan age and cumulative budget. It prints the SHA-256 of the inspected bytes. The provider leaves some computed fields, including the NIC's public address, unknown before provisioning. The reviewed template requests only the private subnet. Verify actual NICs, disks, node count and effective strategy in the provider inventory at launch. For production allocation use the funded `pilot` stage below. It verifies the exact bytes, checks both timer hosts and atomically reserves the attempt before Terraform can create the group.

The cleanup hosts are **bm** (primary) and **fw13** (backup, hostname `fw13pro`). Both run the system timer under the separate `nebius-cleanup` account. Keep fw13 powered, awake and connected for the allocation and cleanup reserve. Before each window, check its clock and network separately from bm. Install the two worker-expiry templates and the failure-alert unit on both hosts. Place the pinned Nebius CLI and Terraform in `/opt/nebius-cleanup/bin` and the reviewed Terraform root in `/opt/ml-infra/bootstrap/nebius`. Initialize each host against the same approved backend with `TF_DATA_DIR=/var/lib/nebius-cleanup/terraform` and `terraform init -lockfile=readonly` as its cleanup identity. Set a protected per-run environment file at `/etc/nebius-cleanup/RUN_ID.env` with cluster ID, project ID, cutoff, provider credentials, state access and executable PATH. Keep the per-run environment root-owned at mode 0600. The inventory file must be readable to the service account (`root:nebius-cleanup`, mode 0640). Use the same approved run variables and backend on both hosts. Preserve the pre-run IDs in `RUN_ID-inventory.json` with `project_id`, `cluster_id`, `group_ids`, `instance_ids` and `disk_ids` arrays for the three inventories. Record approved shared resources and intentionally retained disks. Store the allocated group and VM IDs separately for incident recovery. Configure the VictoriaLogs notifier described below and confirm the receiver before starting the allocation. Arm `worker-expiry@RUN_ID.timer` on both hosts before provisioning. Keep timers active until both cloud and Terraform reconciliation succeed. For early release, first remove the run pools from desired configuration, then use `expire-workers --release-now` with the same run scope and inventory. Review before applying an authorized removal.

For the GPU experiment, close the pilot's inventory and retire its timers. Install and exercise new timer instances on both hosts for the GPU window before creating its support CPU or GPU. Record scope, next tick, baseline and alert receipt on each host. After each create, match the actual group IDs and labels from independent cloud reads. Use a distinct run ID and new timer proofs for the support group and subsequent GPU create.

### Cleanup notifications on fw13

On both cleanup hosts, `worker-expiry@.service` triggers [the failure unit](worker-cleanup-alert@.service). Install [notify-cleanup.py](notify-cleanup.py) and the two pure-Python wheels from [the hash lock](otlp-requirements.txt) in the root-owned, service-readable directory `/opt/nebius-cleanup/notifier`. For example, build a staging directory with `uv pip install --target "$stage" --no-deps --only-binary :all: --require-hashes -r otlp-requirements.txt` before installing it. Give the service its origin in `/etc/nebius-cleanup/alert.env` with `CLEANUP_OTLP_LOGS_URL=https://fw13pro.degu-fir.ts.net:8443/insert/opentelemetry/v1/logs`. Install the ingestion bearer at `/etc/nebius-cleanup/otlp-bearer`, root-owned mode 0600. Systemd exposes it to the dynamic UID through `LoadCredential`. Send OTLP protobuf over verified TLS. Retries retain the event ID.

The [Grafana rule](cleanup-alert.grafana.json) in folder `nebius-worker-cleanup` uses datasource `victoria-logs`. It fires per run and host for cleanup failures in the preceding ten minutes. Import its JSON with Grafana’s alert provisioning API after creating that folder. For an acceptance test, set `CLEANUP_ALERT_REHEARSAL=1` on a unique alert-unit instance via a runtime drop-in and induce an invalid-cutoff failure on the matching worker-expiry instance. Check both journals, then query VictoriaLogs with `{service.name="nebius-worker-cleanup"} run_id:="TEST_RUN_ID"`. Match both event IDs and confirm both instances in Grafana. The cleanup service has a 12-minute execution timeout and 30-second termination grace. On November 21 a shortened timeout killed a hanging test process on both hosts and triggered the same failure route. A timed-out delete can continue at the provider. Check the operation, lock holder and cloud inventory before retrying or releasing a ledger hold. The November 21 test reached Grafana. Delivery currently ends in the Grafana UI. An off-host paging contact would also cover loss of fw13 itself.

### Saved worker plans and fit decisions

Use [check-gpu-plan](../check-gpu-plan) from the Terraform root for all three stages. Source the provisioning identity environment before running the wrapper. Store approval inputs and receipts outside the worker, under the operator's control. `prepare` initializes the approved eu-south1 S3 bucket, state key and default workspace in a private directory with the reviewed provider lock. It creates a saved plan only after the stage and budget checks pass. `recheck` consumes the trusted prepare receipt and checks the live state lineage and serial, source, current ledger bytes, time and exact plan digest. Both commands leave cloud resources unchanged.

```bash
umask 077
./with-credentials ./check-gpu-plan prepare "$plan" --scope "$scope" --ledger "$ledger" \
  --var-file terraform.tfvars --var-file "$run_vars" > "$prepare_receipt"
./with-credentials ./check-gpu-plan recheck "$plan" --scope "$scope" --ledger "$ledger" \
  --receipt "$prepare_receipt" > "$recheck_receipt"
# For the GPU fit decision after measuring throughput
./check-gpu-plan project --scope "$scope" --ledger "$ledger" \
  --measurements "$timings" > "$fit_receipt"
```

| Input | Fields and semantics |
|---|---|
| Approved scope | `stage` is `pilot` for CPU qualification, `support` for the GPU experiment's CPU host, or `gpu` to add the spot GPU. Supply `run_id`, UTC `start` and `cutoff` ending in Z, `project_id`, `subnet_id`, `cluster_id`, `state_lineage`, `state_bucket`, `other_cost_usd` and the SHA-256 of the exact current ledger bytes in `ledger_sha256`. Supply `policy_id` for `support` and `gpu`. The GPU stage also requires the independently observed `support_group_id`. |
| Dated ledger | Supply `revision`, `run_id`, UTC `observed_at` (at most 15 minutes old) and `gpu_intervals` covering all allocations in this experiment. Each entry has `vm`, UTC `start`, and `end` (null while in flight). Overlaps count once per VM. Include posted and accrued-but-unposted spend through observation in `accrued_gpu_usd` and `accrued_non_gpu_usd`. |
| Remaining costs | Supply `cpu_and_boot_hourly_usd`, `gpu_boot_hourly_usd`, `tax_remaining_usd`, `other_remaining_usd` (retention, network, storage and other costs), `cleanup_other_usd` (additional shutdown costs) and `drain_hours` (before cutoff). The guard prices the support and disks through the extra release hour and separately reserves one GPU-hour at the $1.50 cap. Use `post_release_usd` for work priced after GPU drain. Count each expense once. |
| CPU pilot | Keep the window within eight hours. Set `remaining_gpu_hours` to the allowance reserved for later fits. The pilot prices CPU and boot SSD for the entire window plus one cleanup hour. Include accrued spend, tax, retention and cleanup. Its reservation records zero GPU-hours. The spot policy may be blocked during the pilot. |
| Fit measurements | Set `seed` to 27 or 28, `measurement_sha256` to the verified benchmark receipt digest and `checkpoint_every` in updates. Under `samples`, supply arrays of observed seconds for `update_seconds`, `fit_sample_pass_seconds`, `validation_pass_seconds`, `save_seconds`, `startup_restore_seconds` and `export_seconds`. Each evaluation pass covers its complete 6,664-window cohort. |
| Work after training | Under `post_work`, give `confirmation_5163`, `calibration_scoring`, `language` and `clean_reload` a measured `seconds_each` and `when` set to `allocated` or `after-release`. The latter also has `hourly_usd`. The projection prices four checkpoints for scoring, calibration and language tests plus one clean restore. |
| Retries | The operator can record verified progress under ledger `fit_progress["27" or "28"]["control" or "candidate"]`. Record `step`, `evaluated_through` (last fully evaluated scheduled step or -1), `checkpoint_sha256` and boolean `terminal`. A terminal arm needs `export_sha256`. With no record the checker prices the arm from zero. |

The fit receipt includes all three bounds, the ceiling counts, replay and component timings. Exit status 2 with `budget-stop` records that the measured work cannot fit. Before a real window the IAM and FinOps owners must seed the current operator-approved ledger at `prod/mk8s/release-control/ledger.json` in the versioned state bucket. Grant the provisioning identity conditional write to that key. Restrict each host’s timer prefix to its own cleanup identity for writes. The initial ledger contains `attempt_ids: []` and `active_reservation: null`. Scope also contains a unique `attempt_id`, the approved `baseline_sha256` and distinct Nebius account IDs in `cleanup_accounts` keyed by `bm` and `fw13`. Verify worker images, support preflights and MLflow readback at their designated release gates.

Install [the publisher](publish-timer-attestation) and [its oneshot unit](worker-attest@.service) beside the cleanup units. The publisher needs system Python with boto3 and StateDirectory access. Supply the approved JSON as `/etc/nebius-cleanup/RUN_ID-scope.json`, readable by the cleanup account. With both production timers enabled and active, run `systemctl start worker-attest@RUN_ID.service` on each host just before apply. Each publisher verifies its own authenticated Nebius account and inventory reads, remote state, protected run configuration and baseline digest, plus the real systemd timer and its next tick. It writes a versioned proof under `prod/mk8s/release-control/timers/RUN_ID/STAGE/HOST.json`.

After human release checks, run `./with-credentials ./check-gpu-plan apply "$plan" --scope "$scope" --ledger "$ledger" --receipt "$prepare_receipt"` from the trusted provisioning host. This is the mutating command. It checks the private copy of the plan, verifies the exact live ledger bytes and both current host proofs, then uses S3 `If-Match` to reserve the attempt before executing the same copy. Collect the reservation version and provider IDs. An active hold, duplicate attempt, missing/stale evidence or concurrent ledger update blocks the apply. On a failed or ambiguous apply, retain the hold and inspect provider operations and inventory. FinOps closes it with a conditional update after reconciling actual charges and outstanding commitments, retaining the attempt ID history. Issue a new ledger revision and approval for the next stage. The fit projector supplies decision receipts. The training runner still needs to reserve and consume its own job attempts.
