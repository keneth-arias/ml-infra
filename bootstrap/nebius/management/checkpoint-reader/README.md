# Attended checkpoint export

Use this operator-only workflow for an explicitly approved synthetic qualification. Confirm the exact managed target, a still-funded support CPU worker, the original PVC/PV/CSI IDs, a terminal workload, and the restored native admission hold. Verify that Kubernetes and Nebius both report detachment and that no active Pod requests the claim. Record the read-only review before creating anything.

The reader runs the reviewed Python source from an immutable ConfigMap on the existing signed preflight image. It uses the image's checkpoint validation module. Sign and independently verify the source hash, exact identity and render, image digest, support node, original binding, and funded byte limit at the attended operation. Follow the deployment's existing policy. Keep the training submitter closed and use the separately approved operator account for the named reader object and its named exec channel.

The reader Pod mounts only the exact `episodes/<run>/state` subpath, read-only on the PVC source and container mount. Use a restricted CPU-only Pod with a finite deadline, a read-only root filesystem, all capabilities dropped, service-account token automount off, no application credentials, and egress denied. Verify the live ConfigMap UID and bytes, Pod UID, signed image ID, support node, egress policy, and original disk binding before exec. The Pod starts the reviewed script with `--wait-for-operator`. That command checks the read-only mount and waits without reading the checkpoint. Compare the approved render and bound Pod with `python3 verify-pod-labels.py approved-pod.json observed-pod.json`. The bound Pod may carry the Nebius-injected `topology.kubernetes.io/region=eu-south1` label. The verifier rejects every other label change, including a phase that would select a tracking egress policy.

Place the approved JSON identity in the same immutable ConfigMap. It contains the exact logical run, seed, direct head, direct objective, schedule, fit and validation manifest digests, and weights manifest digest. Pass the image's absolute Python interpreter, `-I -B`, exact reader path, `--identity`, and the funded byte bound. The reader verifies each candidate and its dependent selected generation using the signed code. A complete terminal result must match both generation hashes and the durable evaluation metadata.

First record the JSON inspect result. For an approved nonempty checkpoint, repeat with `--export-checkpoint` and the exact inspected `STEP:SHA256`. Stream binary output directly to an owner-only file on the operator host. The host verifier checks the archive member set and SHA-256 digests without extracting or deserializing the checkpoint. Retain its digest and original inspect receipt. Compare the selected and latest hashes with independent terminal tracking metadata when available.

The reader has no artifact upload credentials. An independent export uses a separately approved private versioned destination and validates capacity, creates the exact key conditionally, and checks the returned immutable version and bytes. Keep the original retained PVC in place. Close the named reader and confirm that both attachment layers clear before releasing the workers.
