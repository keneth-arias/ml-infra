# Run the Lima forecast and episode pilot

Use bm to compare the existing Qwen3.5-0.8B direct forecast with a quantile head and a separate six-hour episode classifier. The default for these new experiment profiles is one RTX 5070 Ti per fit, rank-4 LoRA, alpha 8 and the reference FP32 recipe. Compare one change at a time on AirAware's matched station windows. Keep the established single, pair, joint and distributed profiles available to existing runs.

## Handoff

AirAware supplies immutable split manifests, threshold versions, label eligibility, calibrators, scoring code and the pilot warning policy. OpenTSLM supplies a pinned trainer/inference revision, a synthetic fixture and its expected outputs. For each window the product consumes six hourly concentrations, an interval per hour and one calibrated probability for the whole window. The history-only inference job joins the head outputs and calibration artifacts by window ID. Its inputs include the station threshold known at the forecast origin. AirAware attaches station and origin metadata. Record each component digest so a direct forecast with calibrated residual intervals can be deployed even when a candidate head adds no value.

## Local qualification

1. **Build a reproducible runtime.** Extend the pinned forecast image using the build pattern in [Dockerfile.joint](../runtime/Dockerfile.joint). Bind the OpenTSLM SHA, AirAware exporter/scorer SHA, locked dependencies and base snapshot revision to the build. Pin the resulting image by digest. Verify a history-only synthetic export against OpenTSLM's output fixture from inside the image. The current joint image is imported locally; make the new digest pullable from the destination registry before a cloud replay.
2. **Add separate SkyPilot fit and inference profiles.** Reuse [the launcher](../workloads/sky/launch-airaware.sh) and [its retained-volume renderer](../workloads/sky/model-state.py). Mount only the phase's input bundle read-only. A fit receives training data and the permitted validation inputs. Calibration, policy selection and final scoring each use their designated block. Inference receives histories and frozen artifacts. Keep held-out observations in the scoring step. Verify hashes before allocating fit time. Give each fit its own run ID and output directory on the retained model-state volume.
3. **Measure one GPU, then consider two independent fits.** Start with one short fit, restore and export for each new head. Record peak GPU allocation, host memory, free filesystem space, run time and completion status. Use the measured headroom and the active training quotas before scheduling both cards concurrently. Reconcile profile changes with [ml-infra PR #5](https://github.com/keneth-arias/ml-infra/pull/5), which proposes host and per-process GPU limits. Check the rendered pod and effective limits inside the running container. Use the existing CI render, storage and runtime tests before a local smoke run.
4. **Track results and practice recovery.** MLflow records run family, attempt, task, station dataset revision, split/threshold/calibration hashes, LoRA config, code and image revisions, model-state reference and checkpoint hash. Link forecast MAE, interval coverage/width and the AirAware episode report to the same comparison. Interrupt a synthetic run and resume from the last complete generation on a fresh pod. Confirm the same ordered IDs and predictions within the fixture tolerance. A retry must preserve earlier complete artifacts. Monitor bytes across both hostpath volumes on their shared filesystem. Off-host backup remains deferred.
5. **Run a private hourly pilot.** After AirAware freezes the selected model and calibration bundle, deploy an hourly inference schedule via the dev Flux overlay. Keep ad hoc training under SkyPilot. Record measurement, arrival and actual emission times; stale/missing histories produce an abstention with a reason. Use station, forecast origin and release revision as the output key, a single active writer and retry-safe writes. Preserve the original emission time on replay. Verify delayed input, duplicate triggers, a failed job and model rollback. Monitor freshness, station coverage, missed runs and issuance delay. Score only after observations mature. Report event recall, false warnings per observable station-week and useful lead time; keep pilot results internal.
6. **Qualify Nebius after the local pilot.** Select an available regional GPU, storage and spend ceiling for one time-boxed replay in eu-south1. Review the scoped [Terraform plan](../bootstrap/nebius/README.md) and account for registry access, model/data transfer rights and size, CPU/GPU hours and teardown. With provisioning approved, run the identical digests on the same permitted fixture using the production Kubernetes context and separate credentials. Compare ordered IDs, predictions, run metadata, measured cost and resource release. Local filesystem paths and a node's image cache cannot serve as cloud inputs.

**Order of work.** Image and profile verification can start with synthetic inputs. Real episode fits depend on AirAware's label decision and OpenTSLM's exported task schema. The first local milestone is a reproducible forecast and interval reference; add the classifier once that baseline is recorded. Pilot release follows chronological evaluation on a fresh period. Select the forecast-derived probability if it meets AirAware's warning budget and the separate classifier adds no detection benefit. If both candidates miss the budget, run the concentration forecast alone and use the recorded outcomes to investigate the misses.
