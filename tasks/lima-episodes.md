# Run the Lima forecast and episode pilot

Use bm to compare the existing Qwen3.5-0.8B direct forecast with a quantile head and a separate six-hour episode classifier. The default for these new experiment profiles is one RTX 5070 Ti per fit, rank-4 LoRA, alpha 8 and the reference FP32 recipe. Compare one change at a time on AirAware's matched station windows. Keep the established single, pair, joint and distributed profiles available to existing runs.

## Handoff

AirAware supplies immutable split manifests, threshold versions, label eligibility, calibrators, scoring code and the pilot warning policy. AirAware owns the single synthetic fixture in `docs/methodology/episodios-v1`. OpenTSLM supplies a pinned trainer/inference revision and a reference export for that fixture. For each window the product consumes six hourly concentrations, an interval per hour and one calibrated probability for the whole window. The history-only inference job joins the head outputs and calibration artifacts by window ID. Its inputs include the station threshold known at the forecast origin. AirAware attaches station and origin metadata. Record each component digest so a direct forecast with calibrated residual intervals can be deployed even when a candidate head adds no value.

## Local qualification

1. **Build a reproducible runtime.** Extend the pinned forecast image using the build pattern in [Dockerfile.joint](../runtime/Dockerfile.joint). Bind the OpenTSLM SHA, AirAware exporter/scorer SHA, locked dependencies and base snapshot revision to the build. Pin the resulting image by digest. From inside the image, restore the pinned direct checkpoint, pass only the fixture histories and IDs through OpenTSLM, and compare the ordered output IDs, six horizons, units and FP32 predictions to the reference. Record an explicit tolerance and the image and file hashes; input hashes must match exactly. The current joint image is imported locally; make the new digest pullable from the destination registry before a cloud replay.
2. **Add separate SkyPilot fit and inference profiles.** Reuse [the launcher](../workloads/sky/launch-airaware.sh) and [its retained-volume renderer](../workloads/sky/model-state.py). Mount only the phase's input bundle read-only. Fit with a fixed final step and training data, or a chronological inner validation wholly inside the training block. The current wrapper requires train.npz and validation.npz and its joint post-fit exporter uses the labeled validation archive. Give the pilot a distinct entry point and role-specific manifest rather than passing the outer selection/calibration block to that wrapper. Calibration, policy selection and final scoring each use their designated block. For the point baseline stage AirAware's univariate `--history-only` export. Pin the OpenTSLM revision exposing `--require-history-only` in the image and pass the flag. Require an allowlist per task for future inference formats. Test preflight with swapped block hashes, future-bearing files, and a forbidden mount. Keep held-out observations in the scoring step. Verify hashes before allocating fit time. Give each fit its own run ID and output directory on the retained model-state volume.
3. **Measure one GPU, then consider two independent fits.** Start with one short fit, restore and export for each new head. Record peak GPU allocation, host memory, free filesystem space, run time and completion status. Use the measured headroom and the active training quotas before scheduling both cards concurrently. Keep RAM requests for scheduling, allow fits to use available node RAM and assigned GPU memory, and verify the effective settings inside the running container. Use the existing CI render, storage and runtime tests before a local smoke run.
4. **Track results and practice recovery.** MLflow records run family, attempt, task, station dataset revision, split/threshold/calibration hashes, LoRA config, code and image revisions, model-state reference and checkpoint hash. Link forecast MAE, interval coverage/width and the AirAware episode report to the same comparison. Interrupt a synthetic run and resume from the last complete generation on a fresh pod. Confirm the same ordered IDs and predictions within the fixture tolerance. Training rotates older step directories. Copy the chosen complete release to a retained immutable path outside that rotation. Verify image, base weights, checkpoint, input transform, station thresholds, calibrator and policy against the signed-off release manifest before accepting a replay or rollback. Monitor bytes across both hostpath volumes on their shared filesystem. Off-host backup remains deferred.
5. **Run a private hourly pilot.** After AirAware freezes the selected model and calibration bundle, add a new hourly Kubernetes CronJob to the dev Flux overlay. Request one GPU and use concurrencyPolicy Forbid. The training namespace has a two-GPU quota. During pilot hours reserve scheduling headroom for inference by allowing at most one concurrent one-GPU fit, and measure queue delay as part of actual lead time. Test a contention-induced missed run. Keep ad hoc training under SkyPilot. Register one feed with versioned measurements and first arrival times. Record both the forecast origin and actual emission time. Stale or missing histories produce a recorded abstention.

    For each feed, station and origin, bind the active release and input snapshot at the first issue attempt. Publish the logical issuance with a unique key and atomic create. On a retry compare that release, snapshot and output hash to the existing record. Identical retries return the original result and emission time; conflicts stop and are logged. Keep revised model outputs in a replay stream. Crash-test between publishing and recording job success, including a concurrent trigger and a rollback at the same origin. Verify that a late reading can affect only a later issuance. Monitor freshness, station coverage, missed runs and issuance delay. Use only revisions available by the recorded cutoff. Freeze the source-specific target-maturity delay from observed arrival lags before the pilot. Score after origin +6 h plus that delay, pin the observation vintage and audit later corrections independently. Report event recall, false warnings per observable station-week and useful lead time; keep pilot results internal.
6. **Qualify Nebius after the local pilot.** Select an available regional GPU, storage and spend ceiling for one time-boxed replay in eu-south1. Review the scoped [Terraform plan](../bootstrap/nebius/README.md) and account for registry access, model/data transfer rights and size, CPU/GPU hours and teardown. With provisioning approved, run the identical digests on the same permitted fixture using the production Kubernetes context and separate credentials. Compare ordered IDs, predictions, run metadata, measured cost and resource release. Local filesystem paths and a node's image cache cannot serve as cloud inputs.

**Order of work.** Image and profile verification can start with synthetic inputs. Real episode fits depend on AirAware's label decision and OpenTSLM's exported task schema. First verify point exports. The interval/probability reference depends on delivery of AirAware’s tested calibration code and its immutable artifacts. Add the classifier after recording that baseline. Pilot release follows chronological evaluation on a fresh period. Select in validation and freeze before opening test. The held-out replay may veto the release. Choose the forecast-derived probability in validation if it meets AirAware's warning budget and the separate classifier adds no detection benefit. If both candidates miss the budget, run the concentration forecast alone and use the recorded outcomes to investigate the misses.
